# NO Map Overhaul 0.6.0 local preview

Optional multiplayer drawing channels are implemented for local evaluation. This build is not published. A private two-player test confirmed drawing delivery after the transport compatibility fix. The shared BRA update needs a repeat test with this build.

Open **Tools → Channels** on the full map to configure separate **Broadcast** and **Receive only**, turn sharing on, and **Apply**. Broadcast channels send, receive and collaborate. Receive only adds read-only subscriptions. Each list takes max 10 comma-separated names, displayed in lowercase while typing. The visible **Draw to** indicator and numbered Broadcast buttons show and select the destination for new drawings. Shift+1 through Shift+9 and Shift+0 select only from Broadcast channels. Invalid edits leave the active configuration unchanged, and Cancel or Escape discards unapplied edits. Channel controls are saved in the config file and hidden from F1.

Compatible players on the same team receive a drawing only when the sender broadcasts and the receiver subscribes to its channel. For example, a player broadcasting `ifrit` with `command` under Receive only can read command drawings without sending to command. Members who broadcast the same channel can use Eraser or right-click to request an erase from the owner, then redraw a replacement. The owner must also broadcast that channel to accept edits. Receive-only channels remain read-only, and received drawings stay visible until the owner's update arrives. Received routes remain map references. Sharing is off by default and needs no external service. A compatibility patch keeps drawing connection callbacks out of the game's Mirage transport. Use the updated build on the player-host and both clients; compatibility with an unmodified host remains unverified.

The client-only preview does not exchange drawings across factions, with spectators, or on dedicated-server and UDP sessions. A matching channel name never overrides the faction check. Unit-linked BRA arrows share only unit references, with no unit positions or altitude; recipients calculate their measurements from their own live tracks and hide arrows with untracked endpoints. Other unit-anchored drawing types stay local-only. Protocol 4 requires both clients to use this updated build. Channel names are an honor system within the faction, not access control.

Periodic sharing work runs at most 5 Hz with no catch-up after stalls and supports up to 32 peers. Drawing snapshots remain limited to two per second per peer while editing and one refresh every five seconds. Disabling sharing or changing the local session still clears received drawings immediately.

**F1 → Diagnostics → Log network** defaults off. Enable it on both clients when troubleshooting sharing, then save both logs before relaunching. It records connections, handshakes, snapshot counts and rejection reasons with anonymous peer labels and a bounded output rate. Earlier saved settings persist across updates. See [network logging](../USER_GUIDE.md#logging-multiplayer-sharing).

The automated suite checks channel history, binary packet validation, peer handshakes, replay rejection, received-drawing ownership, polling deadlines, and anchor visibility. Private multiplayer tests confirmed drawing delivery, and the author reported a successful repeat test after the BRA update. Remaining cases are listed in [sharing](../SHARING.md) and [testing](../TESTING.md).
