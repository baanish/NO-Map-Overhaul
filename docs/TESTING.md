After restoring the test project, run the focused sharing and collaborative erase tests with:

```powershell
pwsh ./tools/Test-Sharing.ps1
```

The focused command builds before running tests and stops on the first failure. It exercises game-free state logic, not native Steam sends, receive queues, or live roster admission.

Network-log tests pin disabled silence, invariant timestamps, 128 event lines per five seconds, suppression counts flushed during idle updates, no catch-up windows after a stall, and disable/re-enable behavior. They exercise the log limiter without Steam or Unity.

Steam callback ownership tests reject foreign outgoing and incoming handles, including a second connection to the same peer. They preserve the gameplay listener's full connection lifecycle and terminal cleanup when listener metadata is absent, and reject invalid handles. Recovery tests pin an accepted send followed by asynchronous failure, duplicate callback handling, the exact 30-second deadline, three total unknown-peer probes across failures, incoming Hello during backoff, and recovery for a previously compatible peer.

After building the plugin, check the installed Mirage callback signatures and fields, then invoke the compiled ownership prefixes against synthetic Steam handles with:

```powershell
pwsh ./tools/Test-SteamConnectionOwnership.ps1
```

Seven offline cases cover owned, foreign, invalid, and terminal callbacks. This check makes no native Steam calls and does not apply Harmony detours; patch installation requires the game's Mono runtime.

The suite doesn't start Unity or the game. It doesn't cover drawing, map scale, font borrowing, input handling, 3D label stacking, the perf test switching the mod and map, or game-version compatibility.

## Local 0.6.0 preview

A two-player Steam playtest on 2026-10-05 reported missing drawings and unreliable channel changes. A repeat test with diagnostics found the same protocol and assembly build on both clients, 20 outgoing Hello attempts on the host and 29 on the other client, no completed handshake, and no exchanged snapshots. The host's game log twice records Mirage trying to accept a Steam Messages connection and receiving InvalidParam immediately before the drawing session fails. Inspection of the installed Mirage transport confirmed that its callbacks lacked connection ownership checks. The compatibility patch filters those callbacks, and asynchronous failures now trigger bounded recovery.

On 2026-10-06, startup with the installed fix confirmed that both ownership patches loaded under the game's Mono runtime. The log records `Steam gameplay callbacks now require their transport's own connection or listen socket.` and assembly build `35eba305-4f40-4466-aadc-c03e647adead`. The installed DLL matched the built and packaged DLL, SHA-256 `1ee0f57f9ac5b80b050906c5212f834fc55441160a12123cb64dc43ed76e0385`. This verifies patch installation, not multiplayer delivery.

A manual Steam test on 2026-10-06 used the protocol-3 live 0.6.0 installs on Vulcan and Gemini with separate accounts. Paired logs confirm delivery in both directions, with 74 snapshots applied on Vulcan and 73 on Gemini, and no logged send failures. Matching snapshot sequences and shape counts identify the same session in both logs. Channel changes briefly hit receive limits before subsequent snapshots arrived. The author reported that the other drawings worked, but aircraft- and unit-attached BRA arrows were missing. Both logs repeatedly record `omittedAnchored=1`; that build excluded those arrows before transmission. The protocol-4 update allows BRA anchor references and uses live recipient tracks for visibility and measurements.

On 2026-10-06, the author reported that the protocol-4 playtest on both machines looked good. Track loss, reacquisition, and collaborative erase were not separately reported; [sharing validation](SHARING.md#validation-before-release) lists the remaining cases.

On 2026-10-10, two Steam sessions on Vulcan and Gemini checked whether sharing traffic disturbs a teammate without the mod, on game build 24724372. With Vulcan hosting (DLL SHA-256 `f3d4bc40a77c8371d41119cdf8b4d7613df8482a0cfa7332fcd17088c3751359`, network logging on) and Gemini joining the same faction with BepInEx disabled, the host sent 19 Hellos and recorded 9 failed drawing sessions over nine channel changes. Gemini stayed connected throughout. Its verbose Steam log shows each drawing session timing out and reported only through the Messages session-failed callback, never through the connection-status callback that the game's transport reads. With Gemini hosting unmodified and Vulcan joining as a modded client (DLL `3eb223fa97274121fdcd4460780f66d699a68cea43c8f5fad405dc0048fac67b`), the host never surfaced the drawing connection, and both games stayed connected. The 2026-10-05 failure occurred because both players ran the mod, which activates the Messages interface on the receiving side. The same run confirmed that each channel change renewed the probe budget for a teammate without the mod; discovery now keeps that budget for the whole mission. A teammate running a different mod that uses Steam Messages, without this patch, remains untested.

Later on 2026-10-10, a paired Steam playtest of the protocol-5 build (DLL SHA-256 `aa1bbe04aae23da54063fe245c030cff7544326fcfefc0ab021c57ebb53d9014`, network logging on both) had Vulcan host and Gemini join the same faction. Vulcan broadcast `command` and received `command,test`; Gemini broadcast `test` and received `command`. The pair handshook on Gemini's first faction choice, and Gemini drew all seven of the author's drawings: a pen line, a note, two circles with ranges, a BRA arrow from the aircraft, and a five-waypoint route. A channel Apply on Vulcan, adding `test` to Broadcast, re-paired in 0.2 s and restored all eight drawings, and an owner erase reached Gemini. With both broadcasting `test`, Vulcan erased Gemini's three-waypoint route; Gemini accepted the request as owner and the empty snapshot reached Vulcan 0.3 s later. Idle peers exchanged only heartbeats, with no snapshot resends. Neither log recorded a quarantine, a flood reset, or a mod exception. The author asked that drawings on channels other than the selected one draw dimmer.

An automated single-player check through NO Agentic Framework (DLL `f0ed4ba8`, Broadcast `command,test`) then drew a waypoint route on `command` and a circle on `test` on the full map. Drawing to `test`, the route drew at reduced opacity and the circle at full; after Shift+1 selected `command`, the circle dimmed and the route returned to full, with the summed red channel of the circle falling from 190,229 to 126,167 against the map. The waypoint tool kept extending its one route. After comparing 25% opacity with a darkened colour in game, the author chose half opacity and 60% brightness, and the Waypoint tool's guide line now dims with its route; a further check confirmed both states on a three-waypoint route.

A further two-PC session the same day, with Gemini hosting and Vulcan joining (DLL `e715f603`, network logging on both), covered the reverse join order. With Vulcan on BDF and Gemini on PALA, both sharing sessions ran with no eligible teammate and exchanged nothing. The game offers no team change within a mission, and a client that rejoins keeps its faction. With both on BDF, the pair handshook on Vulcan's faction choice and Gemini's two-waypoint route reached Vulcan. When Vulcan's game was killed and rejoined, Gemini dropped and re-added it, the pair handshook again 2 s after it reappeared, and the route reached Vulcan 0.2 s later. No log recorded a quarantine or a mod exception.

Lifecycle checks followed, with Vulcan hosting through NO Agentic Framework so sharing could be switched mid-session. With Vulcan's sharing off while Gemini drew, Vulcan sent nothing; switching it on first never paired, because the probes, sent without Steam's session-restart flag, failed at once on the broken session Gemini's unanswered probe had left. With the flag restored (DLL `d97057d7`), Vulcan received Gemini's two drawings 12 s after switching on, within Gemini's retry cooldown. Switching Vulcan's sharing off cleared its received drawings and closed the channel; Gemini expired the peer 15 s later and stayed connected; switching it back on re-paired within 24 s (DLL `50df2b8a`). Restarting the mission, through the framework or the host's own Restart Mission button, returned the host to the main menu and the client quit; sharing reset on both sides, closing its channels without errors. In two of about twelve sessions the joined client's main thread froze for about a minute, about two seconds after its 60-second probe opened a new drawing connection while the host's sharing was off or just enabled; the client stopped reading its gameplay connection and the server dropped it. The connection guard filtered no close in the second freeze. Sessions with probe failures alone, typing with a probe failure, Enter while typing, both sides connecting at once, and four automated repeats of the full sequence did not freeze. The mod now logs any frame gap over five seconds and any Steam call that blocks past 250 ms, so a recurrence names where the frame stopped. A further client crash in that series came from replacing its plugin DLL while the game ran, not from the mod. A teammate's received circles appeared on the host's minimap, with their range label, and as a 3D ring in the cockpit view.

On 2026-10-17, a two-PC Steam session checked the beta 3 build (DLL SHA-256 `9681f002d54614c5bb6559102c0d513897ebbf110b51fb61f511d905ff8834f3` on both PCs) in Escalation, with Vulcan hosting and Gemini joining over Steam. The author reported that sharing worked, including circles, notes and routes attached to units. Beforehand, Vulcan's crash folder held four reports from sessions where sharing ran, each ending at the game's Steam shutdown with no sharing reset logged before it. This time Gemini closed its game while still paired with Vulcan, then Vulcan closed its own; neither wrote a crash report, and Vulcan's log shows sharing reset before the game's quit sequence and Steam shutdown.

On 2026-10-17, a single-player NO Agentic Framework session checked the in-place redraw with the build that adds it: a three-waypoint route, Undo back to two waypoints, Redo to three, then a switch of the drawing channel. Undo removed the third waypoint's line, marker and number with nothing left behind, Redo restored them, and the route dimmed with its labels after the switch. A teammate's changing drawings use the same redraw but weren't checked between two PCs.

On 2026-10-05, a live-stack UI check at 1920×1080 confirmed that mixed-case Broadcast input displayed `command, medusa` immediately, Shift+C appended lowercase `c`, and Receive input stayed lowercase with Caps Lock. Uppercase Receive text displayed `command, skynet`. The check discarded its drafts and restored the Caps Lock state. Paste follows the same character-validation hook in the installed TextMeshPro input code; clipboard paste was not exercised in this check.

The source compiles against the installed game's assemblies. Unit tests execute the protocol and session logic without Steam or Unity. The local dev build was installed on 2026-10-05, and its DLL hash matched the compiled artifact. An offline live-stack session through NO Agentic Framework and Computer Use confirmed legible selected-channel and sharing-toggle labels with dim highlights at 1920×1080; the author also approved the screenshot. The completed session recorded no errors from NO Map Overhaul. The shorter-copy update, typing and control restoration, and destination visibility during hover still need in-game checks. The earlier observations below apply to their named versions, not to 0.6.0 sharing. [Sharing validation](SHARING.md#validation-before-release) lists the remaining multiplayer checks.
